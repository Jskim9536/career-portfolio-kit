# 업무·프로젝트 근거 가이드

직무와 실제 수행 범위에 맞는 근거를 선택한다. 공학 실험·코드가 없는 업무도 문서·분석·디자인·운영 기록으로 설명할 수 있다. 모든 분야에 같은 기술 지표를 요구하지 않는다.

## 주장별 기록

| 필드 | 기록할 내용 |
|---|---|
| 주장 | 지원자가 포트폴리오에서 말하려는 사실 |
| 상태 | 확인됨 / 본인 진술 / 목표 / 미검증 |
| 근거 | 문서·화면·운영 기록·분석·디자인·로그·영상·코드·PR 링크 |
| 본인 범위 | 기획 / 설계 / 조율 / 운영 / 구현 / 실험 / 분석 중 실제 수행 |
| 검증 조건 | 업무·고객·기간·표본·운영 환경, 해당 시 OS·장비·데이터·버전 |
| 한계 | 확인하지 못한 조건과 일반화할 수 없는 부분 |

구현 여부, 실행 여부, 측정 여부를 각각 확인한다. 수치에는 단위와 실험 조건을 붙인다. 비율 개선을 계산할 때 비교 대상·분모·평가 조건이 같아야 하며 절대값도 함께 남긴다.

## 분야별 유용한 근거

아래는 선택 가능한 예시이며 모두 측정할 의무는 없다.

| 분야 | 근거 예시 | 자주 빠지는 조건 |
|---|---|---|
| 기획·PM | 문제 정의·요구사항·의사결정·출시·운영 결과 | 본인 책임, 출시/기획 상태, 성과 귀속·측정 기간 |
| 디자인 | 문제·가설·설계안·사용성 검증·실제 적용 화면 | 리서치 표본, 본인 설계 범위, 시안/운영 화면 구분 |
| 마케팅·영업 | 캠페인·퍼널·제안·전환·매출·고객 발굴 기록 | 집행 기간·비용·분모·개인/팀 실적·고객 공개 범위 |
| 운영·사업 | 프로세스·정책·협력사 조율·처리 시간·품질 기록 | 전후 업무량·표본·운영 기간·인과와 다른 요인 |
| 로봇·제어 | 좌표계·센서 입력·제어 흐름, 추종 오차, 도달 여부, 실패 궤적 | 실기/시뮬레이션, 속도, 주기, 초기 상태, 관절·구동 제한 |
| 자율주행·모빌리티 | 기준 경로·예측·계획·제어 역할, 경로 길이, 오차, 실패 장면 | 맵·경로·차량 모델·장애물 조건, 동일 비교 환경 |
| 드론 | 좌표·상태 추정·제어 구조, 목표 추종 오차, 지연·실패 로그 | 실비행/시뮬레이션, 외란·모델·초기 조건 |
| 비전·머신러닝 | 데이터 출처·분할, baseline, 지표, 오류 사례 | 평가 데이터 수·누수 여부·장치·측정 구간 |
| 데이터 분석 | 질문·전처리·검증·시각화, 해석 가능한 결과 | 표본·결측·편향·상관과 인과의 구분 |
| 소프트웨어 | 동작 흐름·핵심 코드·실행 결과·테스트 | 실제 배포 여부, 트래픽·지연 측정 조건 |

## 작은 보완 실험 선택

추가 증거가 필요한 경우 기존 업무 기록·분석·산출물 보완을 우선한다. 공학 실험이 적합할 때는 설치부터 시작하는 큰 프로젝트 대신 이미 실행 가능한 코드에서 변수 하나를 바꾼다. 질문, 공통 조건, 비교 방법, 기록할 지표, 실패 기준, 결과 파일 위치를 먼저 정한다. 실패·미도달도 기록한다.

남은 시간에 실행이 어려우면 실험 계획과 필요한 근거를 남긴다. 제공된 로그 분석은 본인 분석으로 인정하되 본인 실행·구현과 구분한다.

## 기업 가치 표현

경험·결과가 적용될 수 있는 업무나 상황을 설명한다. 예를 들어 경로 탐색의 통과 실패 분석은 통로 설계·이동 가능성 검토와 연결할 수 있다. 실제 현장 데이터로 검증하지 않았다면 비용 절감·안전성 확보·생산성 향상을 달성했다고 적지 않는다.
