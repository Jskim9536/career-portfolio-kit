# 포트폴리오 디자인 첨삭과 핵심 정보 중심 구성

채용 담당자가 제목·주요 근거·본인 기여를 빠르게 파악하는 고정 16:9 문서를 만든다. 기본 방향은 **밝은 배경, 큰 결론, 읽을 수 있는 실제 근거, 넉넉한 여백**이다. 토스풍의 명료함과 벤토의 정보 묶음을 참고하되 공식 TDS 적용이나 브랜드 복제라고 부르지 않는다. 기존 사용자 브랜드·회사 지정 양식이 있으면 우선한다.

## 적용 범위

`design-taste-frontend`가 설치돼 있으면 정보 위계·타이포그래피·색상·여백·카드·리디자인 점검에 관련된 부분을 읽고 적용한다. 없으면 이 문서만으로 작업할 수 있다. 공용 키트는 개인의 스킬 설치 경로나 상용 디자인 패키지에 의존하지 않는다.

프론트엔드용 규칙을 문서에 맞게 해석한다. React·Tailwind·애니메이션·다크모드·CTA·웹 페이지 섹션 수를 요구하지 않는다. PDF는 정적이며, 보기 좋은 장식을 위해 생성 이미지·스톡 사진·가짜 제품 화면·가짜 실험 수치를 증거로 넣지 않는다. 실제 그림이 없으면 필요한 캡처를 요청하고 초안 상태를 표시한다.

## 작성·리디자인 순서

1. 초안 또는 기존 HTML/PDF를 읽고 문서 목적·독자·기존 스타일·보존할 근거를 기록한다. 본문을 읽기 전에 색상부터 바꾸지 않는다.
2. 작업 방향을 한 문장으로 제시한다. 예: `채용 담당자가 직접 구현과 검증 결과를 파악할 수 있는 밝고 간결한 엔지니어링 포트폴리오.`
3. 슬라이드마다 `핵심 결론 1개 / 이를 입증할 주요 근거 1개 / 필요한 보조 설명`을 정한다. 실제 결과가 없으면 결론 대신 정확한 목표·질문을 쓴다.
4. 문구와 정보 위계 → 글꼴·크기 → 여백·정렬 → 근거 크기 → 배경·카드 순서로 고친다. 변경 전후 사실·지표·출처와 담당 범위를 유지한다.
5. 실제 PDF를 렌더링해 점검하고 수정한다. CSS나 HTML 검사만으로 디자인 검수 완료라고 하지 않는다.

## 토큰과 글자 크기

1600×900 캔버스 기준 시작값이다. 제목이 길어지면 우선 문구를 줄이고, 증거가 복잡하면 별도 슬라이드로 나눈다. 읽을 수 없는 크기로 줄이지 않는다.

| 요소 | 시작값 |
|---|---|
| 글꼴 | 번들 Pretendard Variable, 굵기 400·600·700 |
| 표지 제목 | 72px, 줄간격 1.15, 최대 2줄 |
| 페이지 제목 | 60px, 줄간격 1.2, 대부분 1~2줄 |
| 본문 | 28px, 줄간격 1.5 |
| 보조 설명 | 22px, 줄간격 1.45 |
| 캡션·축·출처 | 18~20px, 줄간격 1.4 |
| 핵심 수치 | 64~88px, 실제 확인된 값과 단위·조건만 표시 |
| 캔버스 여백 | 좌우 96px, 상단 약 72px, 하단 푸터 영역 확보 |
| 요소 간격 | 8px 단위, 큰 그룹 24~40px |
| 기본 색상 | 흰 바탕·짙은 본문·중립 회색, 강조색 1개 |
| 카드 | 필요할 때만 옅은 회색·24px 안팎의 일관된 모서리 |

색상·수치는 이 키트의 시작값이며 토스 공식 토큰이 아니다. 강한 무늬·우주/회로 배경·큰 워터마크·색채 그라데이션·글래스 효과로 본문을 방해하지 않는다. 텍스트를 실제 배경에서 읽을 수 있는지 확인한다.

## 벤토는 내용을 묶을 때만

- 주요 근거는 큰 영역, 역할·조건·해석은 작은 영역으로 배치한다. 3~4개 정도의 정보가 실제로 필요할 때 사용하고 모든 슬라이드를 카드로 만들지 않는다.
- 내용 수와 카드 수를 맞춘다. 빈칸을 채우려고 가짜 지표·기술·보조 프로젝트를 만들지 않는다.
- 같은 크기의 텍스트 카드 반복보다 실제 그래프·구조도·화면과 짧은 설명을 구분한다. 이미지 자체의 색은 보존하되 카드마다 다른 장식색을 주지 않는다.
- 텍스트만 필요한 장은 카드 없이 정렬·여백으로 묶는다. 같은 좌우 분할을 모든 페이지에 반복하지 말고 전체 너비 근거·구조도·비교·선택적 벤토를 내용에 맞게 고른다.
- 실제 스크린샷의 UI를 벤토 스타일로 다시 그려 증거를 바꾸지 않는다. 전체 맥락과 필요한 캡션·출처를 보존한다.

## 디자인 인수조건

JD 기준표의 communication 항목에 아래 중 적용할 조건을 **작성 전에** 넣는다. 기존 기준이 고정된 작업에서 디자인을 고쳤다는 이유만으로 배점·인수조건을 사후 변경하지 않는다. 출력 결함은 rendering 게이트에서 확인한다.

| 관점 | 확인할 내용 |
|---|---|
| 핵심 전달 | 제목과 주요 근거만 보고 그 장의 주장·질문을 설명할 수 있음 |
| 우선순위 | 제목·주요 근거·보조 설명·출처의 중요도 차이가 시각적으로 분명함 |
| 증거 가독성 | 실제 그래프 축·단위·조건, 구조도 연결, 화면의 관련 부분이 읽힘 |
| 정보량 | 긴 문단·중복 설명·핵심어 장식을 줄이되 검증 조건·개인 기여는 남음 |
| 일관성 | 같은 중요도의 요소에 같은 글자 크기·색·여백·모서리 규칙 적용 |
| 벤토 적합성 | 내용에 필요한 카드만 있고 주요 증거가 작아지지 않음 |
| 출력 안정성 | 폰트 로드 완료, PDF에서도 동일한 위계·색상·줄바꿈·링크, 잘림·겹침 없음 |

리뷰에는 `슬라이드·요소 / 현재 문제 / 정보 전달 영향 / 변경안 / 완료 기준 / 변경 전후 확인`을 남긴다. `더 세련되게` 같은 추상적 피드백으로 끝내지 않는다. 문구·스타일을 바꾼 모든 언어 버전을 재출력하고 점검한다.

위 원칙을 채용용 슬라이드에 맞게 해석했다. 토스 웹사이트·앱의 화면 디자인 전체나 공식 TDS 패키지를 복제·검증한 것은 아니다. 벤토는 이 키트에서 선택할 수 있는 CSS Grid 구성 방식이며 특정 회사만의 공식 규격이 아니다.
