# 사실·문장·공개 범위 검수와 수정

## 사실을 두 번 대조

먼저 정본 자료 ↔ 각 문서, 다음으로 이력서 ↔ 포트폴리오 ↔ 한·영 버전을 대조한다. 한 문서에 있는 잘못된 주장을 다른 문서에도 복사해 일치시킨 것은 검증이 아니다.

- 이름·학교·학위·전공·자격·직함·회사명·기간·재직 상태.
- 직접 구현/분석, 팀 전체 성과, 리드/지원/공동 작업의 구분.
- 수치·단위·통화·분모·측정 기간·최대/평균·비교 기준·실제/목표 상태.
- 프로젝트 기술·버전·장비·실기/시뮬레이션·실행/코드 존재의 구분.
- 수상명·대회·주최·수상일, 링크가 설명하는 사실의 일치.

충돌 시 사용자 지정 정본과 더 직접적인 근거를 우선하고 남는 충돌만 묻는다. 기존 PDF의 오래된 문구를 최신 사실로 자동 채택하지 않는다. 원본 기록 자체가 본인 진술이면 그 범위 내 일치로 보고하며 외부 검증 완료라고 하지 않는다.

## 언어·편집

한국어 맞춤법·띄어쓰기·조사·중복 수식·불명확한 주어와 대상을 확인한다. 명사형은 자연스럽게 `설계·구현·검증·개선` 등으로 마무리하고 의미 없는 `기여`, `참여`, `성공적 고도화`를 구체화한다. 요청 문체가 우선한다.

영어는 행동 동사·시제·관사·수 일치·대문자·자연스러운 표현을 검수한다. `Led` 같은 소유권을 임의로 높이지 않는다. 핵심 의미는 유지하되 한국어와 줄 수·어순을 억지로 맞추지 않는다. 숫자 구분, 날짜, 약어 최초 설명, `%`와 `%p`를 통일한다.

## 기밀·개인정보: 검사 범위

사실 대조와 별개로 공개 가능성을 검사한다. 비공개 자료를 제공했다는 사실만으로 외부 공개 허가로 간주하지 않는다. 제시된 공개 범위·사용자 승인·공개 출처를 확인하고 불명확한 항목만 묻는다.

검사 대상:

- HTML의 화면 텍스트뿐 아니라 주석·숨김 요소·스크립트에 남은 데이터, 로컬 절대 경로.
- 링크·이미지 경로·URL query·서명된 다운로드 주소·내부 대시보드/저장소 주소.
- 실제 스크린샷·표·그래프의 이름·이메일·전화·주문/고객 ID·운영 데이터. 필요하면 OCR을 보조로 쓰되 실제 이미지도 확인.
- PDF 추출 텍스트·주석·링크·메타데이터·첨부파일. 보이는 페이지와 숨은 정보의 차이.
- API 키·토큰·비밀번호·개인키·환경 변수 값, 미공개 매출·가격·고객·로드맵·소스코드·설계 자료.

지원자 본인이 승인한 이름·연락용 이메일·전화·공개 GitHub/포트폴리오는 용도에 맞게 유지한다. 주민번호·상세 주소·계좌·가족정보와 제3자 개인정보는 채용 문서에 불필요하면 제거한다. 회사명·기술명·매출 지표를 모두 기밀로 단정하지 말고 실제 공개 범위와 출처를 구분한다.

자격 증명은 점수표·댓글·로그에 원문을 복제하지 않고 유형과 위치만 기록한다. 불명확한 자료는 식별 불가능한 수준으로 일반화하거나 개인 출력본에서 제외한다. **이미지 위에 박스만 얹거나 HTML에서 숨기는 것은 안전한 삭제가 아니다.** 별도 출력용 이미지에서 민감 픽셀을 제거하고 메타데이터를 점검한 뒤 PDF를 재생성한다. 원본 증거 파일은 변조하지 않고 개인 보관한다. 실제 비밀을 외부 온라인 검사기·번역기·리뷰 서비스에 전송하지 않는다.

자동 문자열 검색으로 기밀·개인정보가 없다고 확정하지 않는다. 자료 접근이 제한되거나 공개 승인이 불명확하면 해당 범위를 unknown으로 기록한다. 이력서 수정 작업을 벗어나는 키 폐기·계정 변경·원격 데이터 삭제를 자동 실행하지 않는다.

## 수정 요청을 제작 스킬에 전달

각 변경은 `criterion_id / 문서·언어·위치 / 문제 / 근거 / 허용된 수정 / 인수조건`으로 전달한다.

예:

```text
기준 application-jd-v1을 유지해 html-a4-resume 지침으로 v2를 작성.
M1: 프로젝트 1에서 직접 구현한 모듈을 근거표 F3에 따라 명시.
O1: 미측정 성능 향상 문구 삭제. 실제 시험 환경과 완료한 산출물로 교체.
privacy: 스크린샷의 제3자 이름을 제거한 별도 출력 자산 사용.
한·영 HTML·PDF 모두 갱신. 기존 v1 보존. 기준을 다시 만들거나 리뷰를 재귀 호출하지 않음.
```

포트폴리오는 `html-pdf-portfolio`에 같은 기준·근거와 시각 자료의 공개 범위를 전달한다. 기존 스타일과 확인된 핵심 근거를 유지하고 순서·제목·설명·가독성을 수정한다. 점수 개선을 위해 실제 근거를 축소하거나 실적을 과장하지 않는다.

## 종료와 미해결 항목

한 차례 수정과 재검수를 기본으로 한다. 새 오류가 확인되면 최대 한 차례 더 수정한다. 새 경험·추가 실험·정본 확인·공개 승인이 필요하면 문장 수정으로 해결했다고 하지 않는다. 그 밖의 수정 파일을 완성해 전달하고 필요한 입력과 남은 판정을 명시한다. 사용자가 수정 횟수·리뷰 전용·출력 형식을 지정하면 따른다.
