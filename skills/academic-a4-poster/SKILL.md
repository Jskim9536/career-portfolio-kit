# Academic A4 Poster

지원자·실무자·연구자의 실제 프로젝트를 학회 발표처럼 읽히는 A4 포스터로 구성한다. 기본 산출물은 편집 가능한 HTML과 A4 1페이지 PDF다. 초안도 실제 검증 상태와 누락 항목을 드러내야 한다.

## 1. 자료를 읽고 필요한 질문부터

사용자가 준 코드·README·보고서·포트폴리오·로그·화면을 먼저 읽는다. 목적, 발표 대상, 출력 크기·방향, 이름·소속, 프로젝트 문제, 본인 기여, 방법, 결과·실험 조건, 그림·표, 출처를 확인한다.

누락 여부는 [content-and-questions.md](references/content-and-questions.md)로 점검한다. 이미 자료에 답이 있으면 다시 묻지 않는다. **본문의 정확성과 배치를 결정하는 핵심 질문을 최대 3개로 묶어 먼저 묻는다.** 사용자의 응답이 필요한 사실을 확정하지 않는다. 초안 요청이면 답을 기다리는 동안 빈 자리와 자료 요청이 표시된 레이아웃을 만들 수 있다. 최종본은 해결되지 않은 핵심 누락을 알리고 초안으로 구분한다.

결과가 없으면 가설·실험 계획을 결과로 쓰지 않는다. 실험 전이면 섹션명을 ‘검증 계획’으로 바꾸고 상태를 명시한다. 수치·실적·저자·소속·논문 인용을 만들어내지 않는다.

## 2. 디자인 레퍼런스와 방향

디자인 전 [design-and-references.md](references/design-and-references.md)를 읽는다. 사용자 레퍼런스가 있으면 그것부터 확인한다. Behance 등은 **정보 위계·그리드·색·그림 배치**의 참고로 사용하고 타인의 문구·그림·로고·연구 데이터를 복제하지 않는다. URL과 실제 확인 범위를 기록한다. 접근이 막힌 페이지를 시각 검토했다고 말하지 않는다.

기본은 세로 A4, 흰 바탕, 짙은 본문, 강조색 하나, 2열 학술형이다. 공학 프로젝트는 시스템 구조·실험 결과를 크게, 연구형은 질문·방법·결과·한계를 선명하게 배치한다. 사용자가 방향을 정하지 않았으면 내용에 맞는 기본안을 제시한다. 디자인 비교를 요청할 때만 두 가지 방향을 비교한다.

## 3. 내용과 문구

대표 프로젝트 하나를 중심으로 다음을 작성한다. 내용에 맞춰 섹션은 조정한다.

1. 제목, 저자·소속, 검증 상태.
2. 핵심 요약 한 문장: 무엇을 어떤 조건에서 구현·검증했는가.
3. 배경·문제·목표.
4. 방법·시스템 구조와 본인 기여.
5. 결과·조건·근거 그림 또는 표.
6. 해석·한계·활용 가능성·다음 검증.
7. 출처·GitHub/데모 링크.

긴 논문을 축소하지 말고 한 번 읽고 핵심을 설명할 수 있게 요약한다. 제목은 검증된 결론 또는 정확한 연구 질문으로 쓴다. 전문 용어는 필요한 것만 남기고 처음에 풀어 쓴다. ‘혁신적’, ‘획기적’ 같은 수식어 대신 방법과 근거를 쓴다. 현장 생산성·비용 절감을 측정하지 않았다면 적용 가능성으로 표현한다.

그림마다 무엇을 보여주는지 캡션을 쓴다. 그래프는 단위·축·실험 조건·비교 기준을 표시한다. 근거 이미지가 없으면 필요한 캡처의 화면·상태·설명·경로를 구체적으로 요청한다. 생성 이미지를 실제 장비 사진·시뮬레이션 화면·실험 결과처럼 사용하지 않는다.

## 4. HTML → PDF

[poster.html](assets/poster.html)을 복사해 작성한다. 템플릿은 구조 안내용이며 실제 지원자 실적이 아니다. 기본 `@page`와 캔버스는 210×297mm, 여백은 내부에 둔다. 가로 요청은 297×210mm로 함께 바꾼다. A4는 초안 규격이다. 향후 A1·A0 등 대형 출력이 필요하면 주최 측 규격을 확인하고 별도 조판한다.

본문 10~11pt, 캡션 약 9pt를 시작점으로 삼고 100% 출력 크기에서 확인한다. 텍스트가 넘치면 문구·중복·부차 정보를 줄인다. 글자를 무한히 줄이거나 `overflow:hidden`으로 감추지 않는다. 이미지 비율과 캡션을 보존한다. QR을 만들었다면 실제 대상 URL을 사용하고 스캔을 확인한다. 링크 미확정이면 가짜 QR 대신 요청 사항을 남긴다.

같은 HTML을 Chromium의 기본 인쇄 엔진으로 PDF 저장한다. 배경 그래픽을 포함하고 브라우저 머리글·바닥글을 제거한다. 폰트·이미지 로드를 기다린 뒤 출력한다. 외부 다운로드나 전역 도구 설치를 필수로 만들지 않는다.

## 5. 검증과 전달

PDF를 다시 열어 ① 1페이지 ② A4 실제 크기 ③ 한글·기호 ④ 잘림·겹침·읽기 순서 ⑤ 그림·축·캡션 ⑥ 링크·QR ⑦ 근거와 문구 일치를 확인한다. PDF를 이미지로 렌더링해 전체와 본문을 검사한다. 가능하면 흑백 대비도 확인한다.

HTML·PDF와 함께 누락 자료·추가 질문·확인한 조건을 전달한다. 초안과 최종본을 구분한다. 파일 생성, 실행, 시각 검증 중 수행하지 못한 단계는 명시한다. 공개 저장소에는 지원자 원자료와 개인정보를 자동으로 업로드하지 않는다.
